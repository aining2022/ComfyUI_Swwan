# Turbo 移除：普通 / 增强双模式

[可编辑工作流](../examples/qwen21-remove-turbo-bluebox-gh-dual-mode.json) · [API 图](../examples/qwen21-remove-turbo-bluebox-gh-dual-mode-api.json) · [基础模型与动态预算说明](QWEN21_REMOVE_BLUEBOX.md)

默认普通模式保持 40% 绿色覆盖。打开节点 **100** 后，增强模式使用原图坐标的块化选区和 **100% 不透明绿色**，最终按块化后的有效范围贴回。仍共用 Turbo INT8、Remove GH 1.0、Sage、9 步完整 sigma、512–1920 动态预算与孤海颜色还原 1.0。

| 控制 | 普通（默认） | 增强 |
| --- | --- | --- |
| 节点 100 | 关闭 | 开启 |
| 选区 | 原有软 mask，不额外填洞或二值化 | 节点 101 块化，再由 102 扣除保护 |
| 绿色覆盖 | 0.4 | 1.0 |
| 贴回 | 普通有效范围 | 块化后有效范围，允许修改新增区域 |

## 操作和排查

1. 节点 1 输入干净原图，节点 2 输入同尺寸实心选区，白色移除。节点 4 可替换为同尺寸保护 MASK，白色保护。
2. 节点 100 是唯一公共模式开关。103 / 107 / 111 的开关输入均已连接到它，勿分别断开修改；连接控件显示的默认值不代表本次实际输入。
3. 节点 101 的 `block_size` 默认 32，范围 8–512，按原图像素解释。沿用 Blockify 的外接框分块方式，边缘块尺寸可不同；它与 BlueBox 的 32 对齐不是同一参数。
4. 节点 113 预览实际允许改动的范围，普通模式不会为此执行块化。增强范围内可能含原始 mask 未选择的像素；必须保留的内容请用保护 mask 排除。
5. 节点 105 / 106 显示两种覆盖强度，114 显示当前实际值。109 / 110 显示两种基础提示词，经 112 选择后，在节点 8 的 `string_b` 追加用户要求；32 预览编码文本。
6. 37 / 38 显示原生裁剪宽高，39 显示动态预算，30 / 31 显示工作画布宽高。预算在缩放和 BlueBox 比例调整前根据当前有效范围＋上下文计算。
7. 22 / 23 / 25 / 26 保存实际输入、原始块、最终融合范围、最终图。25 是最终门控 mask，不是孤海内部羽化权重。

普通模式跳过增强块化分支。增强模式在块化前后都减保护，最后仍按当前有效范围使用原图像素保护选区外和全白保护区。软边由孤海恢复处理，最终门控不重复乘软 mask。

官方编码器使用 resolution=0，采样 latent 来自编码器；孤海 `GH_CropRestore` 消费相同 SEAM，只逆变换一次，颜色还原默认 1.0。工作流使用 RGB 输出。空选区或全部被保护的选区在采样前报错。

## API 与兼容

API 节点 100 的 `value` 为 false/true；节点 101 的 `block_size` 默认 32。配套调用脚本增加 `--removal-mode normal|enhanced` 和 `--block-size`；缺省为普通模式，公共 `extra_prompt` 及原参数保持。

本次复用已经注册的节点，不新增 Python 推理节点或插件依赖。需要已有动态预算版本 `3a439fa`；已运行该版本的实例可以直接导入双模式图。保留[原普通版](../examples/qwen21-remove-turbo-bluebox-gh-expanded.json)作为回归基线。本次不自动更新或重启线上实例。


测试直接运行现有 Swwan 节点，检查普通模式预处理像素一致、软 mask、惰性分支、块化保护、贴边、多块、空选区、原生孤海恢复和最终范围保护。

详细 L20 图片与逐次证据位于配套 `replicate-models/image/qwen21-eraser-native/validation/enhanced-20261029/`；完整操作与 API 示例见 `ENHANCED_REMOVAL.md`。增强模式效果独立验收，不能因执行成功或普通模式有效便认定它更好。

本次 L20 完成 3 素材 × 3 seed × 2 模式。普通模式与原版 seed 42 的三个素材对照全部零像素差异；两种模式相对实际加载原图的有效范围外不变，1761 个保护像素不变。增强的小物体样例通过，但水印标志／结构保真和厨房完整目标清除未通过，因此增强保持实验配置，默认关闭。小物体、水印、厨房增强中位执行耗时为 2.876、2.019、14.290 秒；不代表总体速度优势。厨房源文件实际为 JPEG，保护检验以 ComfyUI 实际解码原图为基准，解码差异另有记录。
